# Follow-on targets that reuse the Wilson-quotient machinery (assessed 2026-10-03)

## A157250 — Wilson numbers (recommended)

n is a Wilson number if P(n) + e(n) ≡ 0 (mod n²), where P(n) = ∏_{a≤n, gcd(a,n)=1} a and
e(n) = +1 if n ∈ {1,2,4}, n = p^k or 2p^k (p odd), else −1. Known: 1, 5, 13, 563, 5971,
558771, 1964215, 8121909, 12326713, 23025711, 26921605 — complete only to 5·10⁸
(Agoh–Dilcher–Skula 1998, who used the Crandall–Dilcher–Pomerance Wilson-quotient table,
which is why the bound is 5·10⁸). Heuristic count below N is (6/π²)·ln N (11 known vs. 12.2
predicted at 5·10⁸), so the expected number of NEW terms is

| search bound N | 10¹¹ | 10¹² | 3·10¹² |
|---|---|---|---|
| expected new terms | 3.2 | 4.6 | 5.3 |

### Reduction to per-prime data (derived and verified here)

For p^k ∥ n, write n = p^k·m. With G_k = ∏_{j<p^k, p∤j} j (Gauss factorial),
A(m) = ∏_{ℓ|m, ℓ prime} ℓ^{−φ(m)/(ℓ−1)} (a unit mod p^{2k}):

    P(n) ≡ A(m)^{φ(p^k)} · G_k^{φ(m)}   (mod p^{2k})        for all p^k except p=2,k=1
    P(2m) ≡ A(m) · (−1)^{φ(m)/2}         (mod 4)             for m ≥ 3 odd

(uses the block identity ∏_{j<p^k,p∤j}(cp^k+j) ≡ G_k mod p^{2k}, i.e. the generalised
Wolstenholme congruence; it fails only for 2¹, hence the special case). Verified against the
direct product for every prime-power component of every n ≤ 3000, and the resulting Wilson
test reproduces {5, 13, 563, 5971} below 30000 (see scratch Python in the session log;
re-derive from `tools/` when implementing).

Writing G_k = −1 + p^k·w(p^k) (w(p^k) = generalised Wilson quotient, = Wilson quotient w_p
for k = 1) and linearising for m ≥ 3 (φ(m) even):

    P(n) ≡ 1 + p^k·[ q_{p^k}(A(m)) − φ(m)·w(p^k) ]   (mod p^{2k}),
    q_{p^k}(A(m)) ≡ −Σ_{ℓ|m} (φ(m)/(ℓ−1))·q_{p^k}(ℓ),   q_{p^k}(x) = (x^{φ(p^k)}−1)/p^k mod p^k

so the component test at p^k is   Σ_{ℓ|m} (φ(m)/(ℓ−1))·q_{p^k}(ℓ) + φ(m)·w(p^k) ≡ 0 (mod p^k),
plus the m ∈ {1,2} cases (n = p^k: G_k ≡ −1 mod p^{2k}; n = 2p^k: w(p^k) + q_{p^k}(2) ≡ 0).
n is a Wilson number iff every prime-power component passes.

### Pipeline

1. **Wilson quotients w_p mod p for all primes p ≤ N/2** (the n = 2p family needs N/2; everything
   else N/3). Run `pw13` (this repo) over all e-classes with a small patch to dump residues in
   binary (5 bytes per prime). At these sizes Stage 2 dominates: 73 µs/prime measured.

   | N | primes ≤ N/2 | Spark-days (CPU, both Sparks halve it) | table size |
   |---|---|---|---|
   | 10¹¹ | 2.1·10⁹ | 1.8 | 10 GB |
   | 10¹² | 2.0·10¹⁰ | 16 | 100 GB |
   | 3·10¹² | 5.6·10¹⁰ | 47 | 280 GB |

   atom2 has 3.5 TB free. Validate the table against `wilsontest` on spot ranges as done here.
2. **Generalised Wilson quotients w(p^k) for k ≥ 2, p^k ≤ N/2** (p ≤ √N ≤ 10⁶): G_2 mod p⁴ from
   (p−1)! mod p⁴ and the elementary symmetric functions e₁,e₂,e₃ of {1/j : j<p} (O(p) per prime,
   128-bit arithmetic, minutes total); G_k for k ≥ 3 by the same block recursion or directly with
   GMP (tiny).
3. **Composite sieve**: for each prime P ≤ N/2 and each m ≤ N/P coprime to P, test the P-component
   (needs w_P from the table, φ(m) and the prime factors of m from an spf sieve, and q_P(ℓ) by one
   modexp per prime ℓ | m); survivors (probability 1/P) get all their components tested. Work
   ≈ N·ln ln N·(small) ≈ 10¹³ simple ops for N = 10¹²: a day or two on 20–96 cores. Random access
   into the w_p table → keep it in RAM (100 GB fits a Spark; 2 TB box trivially).
4. **Self-test**: the same pipeline run to 5·10⁸ must output exactly the 11 known terms.
   Unit tests: formula vs direct product for n ≤ 10⁶; A157249 b-file (exact w(n), n ≤ 200).
5. **Verification of a hit**: direct product of units mod n² (O(n) 128-bit steps, like
   `tools/wilson_brute.c`; n = 10¹² is about an hour on 8 cores), independent of the formula.

Effort: ~3 days of implementation and validation, ~1–2 weeks of Spark CPU time for N = 10¹²;
the Spark GPUs are idle during this, so A197632 can run concurrently.

## A197632 — Lerch primes (GPU side project; low probability of a new term)

p is a Lerch prime iff Σ_{a=1}^{p−1} a^{p−1} − (p−1)! − p ≡ 0 (mod p³), equivalently
Q₂ + Q₁² − 2Q₁ ≡ 0 (mod p) with Q_r = Σ_a q_p(a)^r mod p (Fermat quotients). Known: 3, 103, 839,
2237, 42447347; exhaustive to 2·10⁸ (Veljko Vranić, Aug 2026, github.com/veljkovranic/lerch,
Rust, primitive-root recurrence u_{j+1} = u_j + q_p(g) + k_j·v_{j+1}, one step per residue,
5.7 ns/step on an M1 core). No sub-quadratic method is known (Vranić discusses and rejects
batch-Bernoulli approaches); total work to N is Σ_{p≤N} p ≈ N²/(2 ln N) steps.

| N | steps | 96-core box (CPU) | both GB10 GPUs at 1–3·10¹¹ steps/s each |
|---|---|---|---|
| 10⁹ | 2.4·10¹⁶ | 16 days | 0.5–1.4 days |
| 2·10⁹ | 9.4·10¹⁶ | 2 months | 2–5 days |
| 4·10⁹ (u32 ceiling) | 3.6·10¹⁷ | 8 months | 7–20 days |

GPU design: one thread per prime with a fixed modulus (so Montgomery/Barrett constants are
per-thread and all arithmetic is 32-bit for p < 2³²), primes sorted so a warp's 32 primes
have equal step counts, batches of ~10⁵ primes, checkpoint per batch. Validate bit-for-bit
against Vranić's published per-prime residues (release archives cover all p ≤ 2·10⁸) and
against a Python bigint definition check on random primes. Beyond 4·10⁹ the arithmetic
becomes 64-bit and 3–4× slower.

Payoff: P(a(6) exists in (2·10⁸, 4·10⁹]) ≈ ln ln(4·10⁹) − ln ln(2·10⁸) ≈ 0.15; the guaranteed
result is the bound comment 2·10⁸ → 4·10⁹ (credit Vranić's 2·10⁸ and method).
Effort: 1–2 days for the kernel and harness, then 1–3 weeks of GPU time.
